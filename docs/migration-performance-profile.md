# #118 Physical Canvas performance capture in the existing geometry ZIP

The existing **Export geometry diagnostics (ZIP)** button now measures the selected Physical renderer before running its unchanged legacy geometry capture. New ZIP members are `performance-profile.json`, `performance-samples.json`, and `browser-info.json`. When the selected engine is not Physical, the performance profile explicitly records unavailability; the geometry export still works.

The browser runs sequential cases with event-loop yields: 1 cold/full sample after explicit optical-session reset, 3 cached/full samples, 3 grid-off samples, 3 interactive-guide samples, and 5 camera-only Pan rotations. The profiler uses shallow model clones and does not write to the live model. The renderer and physics are the actual Physical Canvas pipeline, not a mocked workload. Existing diagnostic capture restores the legacy image, then the currently selected engine is repainted. During capture the export button is disabled to prevent overlapping sessions.

The `performance-profile.json` file contains per-scenario wall-time median, p95, minimum, maximum, and stage timings. `performance-samples.json` includes each sample's timing breakdown, `stroke()` calls, exact ray solves, cache reuse, guide count, and unresolved status. Browser information includes canvas size and device pixel ratio. Stages **do not all add**: painter total contains validation, fill projection and Canvas paint; `wallMs` includes graph configuration and execution overhead. These measure synchronous browser main-thread work, not GPU presentation or displayed FPS. The cold run is intentionally first; compare its result with warm trials and isolate ground-grid cost using grid-off versus cached-full. The original geometry ZIP remains an independent legacy scene audit, and does not claim to be a Physical screenshot.

The profiler can temporarily take time to finish; the original scene configuration is retained. A failed scenario is recorded in the profile instead of being presented as zero cost. Capturing the original legacy audit can itself be expensive. Tests verify immutable model, grouping and exported members; real-world browser timings must come from a user-generated ZIP.
